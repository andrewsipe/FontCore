How tools use it

Each tool copies the slice of FontCore it needs into its own FontCore/ folder. A tool installs from GitHub on its own, with no symlink, no sibling clone and no second install.

Choosing the slice

A tool lists the modules it uses in its own pyproject.toml:

[tool.fontcore-vendor]
modules = ["core_console_styles", "core_file_collector"]

The sync script copies those modules plus every FontCore module they import, and writes FontCore/VENDOR.md, which records the FontCore version and commit the copy came from.

Checking and syncing

python tools/vendor_fontcore.py check            # every sibling project with the table (read-only)
python tools/vendor_fontcore.py check ../Ebrium  # one project
python tools/vendor_fontcore.py sync ../Ebrium   # copy, stamp, remove stale modules
Check saysIt meansWhat to do
BEHINDThe vendored file matches an older FontCore revision.Run sync.
LOCAL CHANGESThe vendored file matches no FontCore revision.Fold the edit back into FontCore, then sync.
MISSING / EXTRAA needed module isn't there, or one no longer needed is.Run sync.

check exits 1 when a project is out of sync.

Never edit a vendored copy. Fix it in FontCore, tag a release, and sync the tools. An edit made in a tool is overwritten by the next sync.

How a change reaches the tools

  1. Change FontCoreEdit src/FontCore/ and run the tests.
  2. ReleaseBump version in pyproject.toml and src/FontCore/__init__.py, commit, and tag vX.Y.Z.
  3. SyncRun check; it lists the tools whose modules changed. sync each one.
  4. Release the toolsBump each tool's version, add a changelog entry, run its tests, commit and push.
